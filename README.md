# Calculator Service & Load Generator (Go implementation)

Высоконагруженный HTTP-сервер вычислений и распределенный генератор нагрузки, переписанные с Python на Go. Проект демонстрирует экстремальное быстродействие (до 100k RPS) за счет применения Actor-модели, неблокирующих структур данных и оптимизации сетевого стека Go.

## Архитектурные особенности

* **Максимально быстрый `POST /calc`**: Обработчик запроса не ждет окончания вычислений в Си/Rust библиотеках. Он выполняет валидацию, фиксирует метрики и мгновенно сбрасывает задачу в буферизированный канал (Actor Model), возвращая `200 OK`. 
* **Потокобезопасность без Mutex**: Изменение глобального состояния вычислений производится строго в одну фоновую горутину-воркер. Это гарантирует детерминированность математических операций и FIFO-последовательность без накладных расходов на блокировки.
* **Кастомный Ring Buffer для Prometheus метрик**: Подсчет RPS за последние 60 секунд реализован в виде кольцевого буфера на базе атомарных инструкций процессора `Compare-And-Swap` (CAS). Данные очищаются "лениво" в момент записи без использования фоновых тикеров.
* **Асинхронный расчет перцентилей**: Замеры времени вызовов CGO-функций накапливаются локально воркером и раз в секунду сбрасываются в фоновый агрегатор метрик для сортировки и вычисления p95/p99. Это полностью изолирует тяжелые вычисления от основного бизнес-пакета.
* **Highload-генератор нагрузки**: Переписан на конкурентные горутины с использованием пула `Keep-Alive` TCP-соединений (`MaxIdleConnsPerHost`), что предотвращает исчерпание сетевых портов ОС (`TIME_WAIT` шторм) под экстремальной нагрузкой.

## Требования для запуска

* Go 1.22 или выше
* Скомпилированные динамические библиотеки `libcalculator.so` и `libcalculator_rust.so` в корне проекта (если необходимо пересобрать, используйте скрипт `build.sh`).

## Инструкция по запуску

Так как проект использует динамическую линковку CGO, при запуске бинарных файлов необходимо явно указывать операционной системе путь к `.so` файлам через переменную окружения `LD_LIBRARY_PATH`.

### 1. Запуск сервера

Из корня проекта выполните команду:

```bash
LD_LIBRARY_PATH=. go run cmd/server/calculator_server.go --port=8080 --interval=5.0
```

Флаги сервера:
* `--host` — IP-адрес для прослушивания (по умолчанию `0.0.0.0`)
* `--port` — Сетевой порт (по умолчанию `8080`)
* `--interval` — Интервал вывода периодических отчетов в консоль в секундах (по умолчанию `5.0`)

### 2. Запуск генератора нагрузки

В отдельном терминале запустите нагрузочный тест (также из корня проекта):

```bash
go run cmd/generator/generator.go --threads=50 --interval=0
```

Флаги генератора:
* `--url` — Эндпоинт сервера (по умолчанию `http://localhost:8080/calc`)
* `-n`, `--threads` — Количество параллельных горутин-воркеров (по умолчанию `10`)
* `--interval` — Пауза между запросами в секундах, поддерживает float. `0` — генерировать нагрузку максимально быстро (по умолчанию `0.1`)
* `--timeout` — Таймаут HTTP-запроса в секундах (по умолчанию `5.0`)

### 3. Просмотр метрик

Сервер отдает метрики в стандартном формате Prometheus (Line Exposition Format `version=0.0.4`) по адресу:
```bash
curl http://localhost:8080/metrics
```

Вывод содержит:
* Посекундный RPS за последнюю минуту (`http_requests_per_second` с ярлыком `offset_seconds` от 0 до 59).
* Метрики времени выполнения Си и Rust функций (`c_function_duration_seconds` и `rust_function_duration_seconds` с квантилями `0.95` и `0.99`).

## Graceful Shutdown

Оба компонента корректно обрабатывают системные сигналы завершения (`SIGINT` / `SIGTERM` / `Ctrl+C`):
* **Сервер** прекращает прием новых запросов, дожидается завершения активных HTTP-сессий (таймаут 5 секунд), бережно вычитывает оставшиеся задачи из каналов, фиксирует финальное состояние вычислений в консоль и плавно останавливается.
* **Генератор** мгновенно прекращает отправку пакетов, закрывает сетевые соединения и выводит суммарную статистику успешных запросов и ошибок.
